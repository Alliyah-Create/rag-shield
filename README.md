# RAG-Shield: Agentic AI Security & Poisoning Detection

An automated, multi-agent security pipeline designed to protect Retrieval-Augmented Generation (RAG) systems from **Data Poisoning** and **Indirect Prompt Injection** attacks (mapped to **OWASP LLM Top 10: LLM01**).

##  The Problem
Enterprise RAG pipelines are highly vulnerable to data poisoning. Adversaries can inject maliciously crafted documents into a knowledge base. When the Vector Database retrieves these poisoned chunks, the LLM executes hidden instructions, leading to data leakage, hallucinations, or security bypasses.

##  The Solution: Agentic Architecture
Instead of a single monolithic prompt, RAG-Shield uses a **Multi-Agent Architecture** with strict Separation of Concerns to ensure security and reliability:

1. ** Worker Agent:** Translates the user query into embeddings and retrieves the top-k most relevant context chunks from the Vector Database (ChromaDB).
2. **🛡️ Guard Agent (The Shield):** Intercepts the retrieved context *before* it reaches the LLM. It analyzes the text for malicious intent, system overrides, and prompt injection.
3. **🤖 Main LLM:** Only generates a response if the Guard Agent certifies the context as "CLEAN".
4. **📝 Observability Layer:** Automatically logs all security decisions, timestamps, and blocked payloads to an audit trail (`security_audit_log.json`) for compliance and debugging.
## 🛠️ Technology Stack
- **Core Language:** Python
- **AI & LLMs:** OpenAI API (GPT-4o-mini), LangChain, LangChain Core
- **Vector Database:** ChromaDB (Semantic Search & Embeddings)
- **Security Concepts:** OWASP LLM Top 10, Agentic Guardrails, Heuristic Analysis, Observability/Logging
